# Business Logic Model — U-KNOWLEDGE

단위: 문서 등록, 추출, 공식 검색, 기사 확정, 근거 원문. Agent 선정 로직은 이 단위에 없다.

---

## 핵심 흐름

### 정책·의사결정 업로드

1. 사용자가 카드(정책 또는 의사결정)에서 파일과 메타를 제출한다
2. 허용 형식만 받는다: 정책은 PDF·텍스트·HWP. 의사결정도 동일 형식으로 둔다
3. Extraction이 텍스트를 뽑는다. 실패하면 업로드 전체를 거절하고 파일을 남기지 않는다 (K6 A)
4. 성공 시 파일·추출 텍스트·summary(추출 앞부분, 사용자가 수정 가능)를 저장한다 (K4 B)
5. 같은 파일명·내용으로 다시 올리면 새 버전을 추가한다. 이전 버전은 남긴다 (K7 A)

### 공식 검색

1. 질의는 허용 도메인 목록에만 나간다
2. 허용 밖 URL·도메인은 검색하지 않고 근거로도 쓰지 않는다
3. 검색 실패는 숨기지 않는다. 결과 목록은 비운다
4. 결과 그 자체는 근거가 아니다. 사용자가 ‘후보로 넣기’를 해야 Article(미확정)이 된다 (K3 C, K5 C)
5. 확정한 뒤에만 listRelated와 원문 근거로 쓴다. FR-7.9는 확정 후에 공식 출처를 근거로 쓸 수 있다는 뜻으로 적용한다

### 기사

1. 시드, 직접 등록(제목·URL 또는 파일), 검색 결과→후보가 모두 Article이다 (K1 B)
2. 미확정은 후보 목록에만 보인다
3. 확정 후에만 Agent 근거·원문 확인 대상이다
4. 확정 해제가 가능하다. 해제 후 근거에서 빠진다 (K7 A)
5. 데모 포용금융 기사는 확정 상태로 시드한다

### 관련 조회 (listRelated)

- 입력: 사업부문, Tag 목록
- 정책·의사결정: 부문이 맞고 Tag 교집합이 있는 항목 (Tag가 비면 부문만)
- Article: 위와 같되 **확정된 것만**
- 점수·랭킹 없음. GoalAgent가 이 목록에서 고른다

### 원문 확인 (US-C-01)

EvidenceRef로 PolicyDocument / DecisionDocument / Article(확정)을 연다. 문서명, 출처, 날짜, summary(또는 Agent가 넘긴 참고 문구), 원본 파일 또는 URL.

## 변환

| 입력 | 결과 |
|---|---|
| 파일 바이트 | Extraction → extractedText. summary 초기값 = 앞부분(상한은 규칙 문서) |
| 검색 히트 | 화면 목록. 후보로 넣으면 Article(confirmed=false) |
| 확정 | Article.confirmed=true. EvidenceRef 발급 가능 |
