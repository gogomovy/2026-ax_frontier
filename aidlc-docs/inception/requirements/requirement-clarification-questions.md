## 이미 확정으로 받아들인 1차 답변

- 범위: 종합기획부 MUST + SHOULD. 다른 Persona 화면은 이번 구현에 넣지 않되, 이후 연결 가능한 구조
- 전파(Journey D): 저장·데이터 모델만. 사업부서 화면은 이후
- 진입: Mock 로그인 → 종합기획부 권한 → 은행 Dashboard
- UI/Agent: 한/영 전환, 기본 한국어
- 프론트/백엔드 프레임워크: Construction에서 결정. 코드 위치는 `apps/web`, `apps/api` 모노레포. 저장은 PostgreSQL
- LLM: OpenAI API
- 실행: 로컬만
- Attention: LLM이 고르고 근거 데이터 ID를 붙임. 사업부문별 Attention
- 목표 수치: 방향 + 범위, 확정 숫자는 사용자
- HWP 파싱 이번 범위 포함
- 실시간 웹/보도자료 검색 포함
- SHOULD: B~G 전부 (외부 검색은 13번 C로 포함)
- 여신 상세: 중간 깊이 UI. 비교는 현재값·전년 동분기·증감액·증감률·Agent 요약. 종합수익은 여신 종합수익 단일 값
- Security extension: 미적용
- Resiliency baseline: 적용
- PBT: 전면 적용
- 데모 데이터: Mock + 관리 화면에서 숫자·목표 변경 가능
