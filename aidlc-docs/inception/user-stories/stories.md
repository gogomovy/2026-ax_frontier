# User Stories: AX프런티어 AI Agent — 종합기획부 Persona

계획: `aidlc-docs/inception/plans/story-generation-plan.md`  
요구사항: `aidlc-docs/inception/requirements/requirements.md`

목차는 Journey A→B→C→D, 각 Journey 안에서 Feature다. 본편은 화면·주요 행동 단위이며 수용 기준은 Given / When / Then이다. 보조는 짧게, 수용 기준은 불릿이다. 스토리·수용 기준은 한국어, ID만 영어다.

레이아웃·차트·버튼 위치는 요구사항 6절대로 Construction에서 정한다. 이 문서는 사용자 행동과 합격 조건만 고정한다.

## 진입

### US-LOGIN-01 종합기획부로 로그인하여 은행 Dashboard에 들어간다

- **페르소나**: P-SP
- **FR**: FR-1.1, FR-1.2, FR-1.3, FR-1.5, FR-2.1, FR-3.1
- **유형**: 본편
- **E2E**: 1

**스토리**: 종합기획부로서, 은행 현황부터 보기 위해, 내 권한으로 로그인해 빈 채팅이 아니라 이미 Attention이 있는 Dashboard에 들어가고 싶다.

#### 수용 기준

**Given** Mock 로그인 화면에 종합기획부, 신용리스크관리부, 영업점 계정이 모두 있다  
**When** 종합기획부 계정으로 로그인한다  
**Then** 은행 전체 Dashboard로 들어가고, 빈 채팅창만으로 시작하지 않으며, 진입 시 Agent가 이미 Attention 또는 보고를 보여 준다

**Given** 로그인한 사용자는 종합기획부이다  
**When** 상위 영역을 본다  
**Then** 은행 Dashboard, 경영목표 설정, 데이터베이스로 이동할 수 있다

**Then** 권한·Persona 식별이 이후 화면 연결에 쓰일 수 있게 데이터와 라우팅에 남는다. 실제 SSO는 없다

#### INVEST

독립: 시드 계정만으로 시연. 협의: 로그인 UI 형태. 가치: 올바른 권한으로 현황부터 본다. 추정: 한 화면. 작음: 로그인+진입. 검증: 위 GWT.

### US-LOGIN-02 신용리스크관리부·영업점은 로그인 후 이후 구현 안내를 본다

- **페르소나**: P-CR, P-BR
- **FR**: FR-1.1, FR-1.2, FR-1.4, FR-1.5
- **유형**: 본편
- **E2E**: 없음 (범위 스토리)

**스토리**: 신용리스크관리부 또는 영업점 담당자로서, 잘못된 업무 화면이 열리는 것을 피하기 위해, 이번 Prototype에서는 이후 구현 안내만 보고 싶다.

#### 수용 기준

**Given** Mock 로그인 목록에 신용리스크관리부 계정과 영업점 계정이 있다  
**When** 그중 하나로 로그인한다  
**Then** 해당 Persona의 실제 업무 화면은 없고 ‘이후 구현’ 안내만 보인다

**Then** Persona 식별은 데이터와 라우팅에 남아, 이후 그 화면을 붙여도 같은 계정으로 들어갈 수 있는 구조다

#### INVEST

독립: 안내 화면만. 협의: 안내 문구. 가치: 세 Persona 로그인을 보여 주되 범위를 지킨다. 추정·작음: 한 화면. 검증: 위 GWT.

## Journey A — 은행 Dashboard

### US-A-01 은행 Dashboard에서 사업부문 카드와 Attention 요약 목록을 본다

- **페르소나**: P-SP
- **FR**: FR-2.1, FR-4.1, FR-4.3, FR-4.4, FR-4.5, FR-4.7, NFR-3.1, NFR-3.3
- **유형**: 본편
- **E2E**: 2

**스토리**: 종합기획부로서, 경영진이 어디를 봐야 하는지 한눈에 알기 위해, 사업부문 세계관과 부문별 Attention 요약 목록을 보고 싶다.

#### 수용 기준

**Given** 종합기획부로 은행 Dashboard에 있다  
**When** 상단 사업부문 카드를 본다  
**Then** 여신, 수신, 퇴직연금, 자산관리, 신탁, 외환, 카드가 보인다

**Given** 카드 클릭 전 메인 Dashboard다  
**When** AI 주요 Attention을 본다  
**Then** 사업부문별 Attention 1~2개가 notification list 형태의 요약 목록으로 보이고, 확인·보고 요청과 UI에서 구분된다

**Given** 여신 Attention을 생성할 실적·목표·정책 요약이 있다  
**When** 여신 Attention이 목록에 오른다  
**Then** LLM이 고른 항목이고 각 항목에 근거 데이터 ID가 있다. 근거 ID 없는 Attention은 완료로 보지 않는다

**Given** 여신이 아닌 부문의 Attention이 목록에 있다  
**When** 그 문구를 본다  
**Then** 고정 Mock 문구이며, 그 부문에 LLM을 돌리지 않는다

#### INVEST

독립: Dashboard 시드. 협의: 카드·목록 비주얼. 가치: 어디를 볼지 고른다. 추정·작음: 메인 화면 보기. 검증: 위 GWT.

### US-A-02 확인·보고 요청을 Attention과 구분된 목록으로 본다

- **페르소나**: P-SP
- **FR**: FR-4.3, FR-4.9, FR-4.9.1, FR-4.9.2
- **유형**: 본편
- **E2E**: 2

**스토리**: 종합기획부로서, 다른 조직이 올린 요청과 Agent가 고른 Attention을 섞지 않기 위해, 확인·보고 요청을 별도 목록으로 보고 싶다.

#### 수용 기준

**Given** 공유 저장소(PostgreSQL)에 시드된 확인·보고 요청이 있다  
**When** 은행 Dashboard에서 확인·보고 요청 영역을 본다  
**Then** Attention과 다른 영역에 목록이 보이고, 화면 전용 Mock이 아니라 그 저장소 레코드를 읽은 결과다

**Then** 시드 예시는 사업부서 성과 확인 요청, 전기 사업 성과보고, 경영방향 확인, 영업점·지역본부 보고를 포함한다

#### INVEST

독립: 시드 요청. 협의: 목록 레이아웃. 가치: 타 조직 요청을 놓치지 않는다. 추정·작음: 한 영역. 검증: 위 GWT.

### US-A-03 여신 카드로 상세에 들어가 해당 Attention과 근거를 다시 본다

- **페르소나**: P-SP
- **FR**: FR-4.2, FR-4.6, FR-4.8
- **유형**: 본편
- **E2E**: 3

**스토리**: 종합기획부로서, 여신에 왜 Attention이 붙었는지 이어서 보기 위해, 여신 카드로 상세에 들어가 그 Attention과 근거를 다시 보고 싶다.

#### 수용 기준

**Given** 은행 Dashboard에 있다  
**When** 여신 카드를 누른다  
**Then** 여신 상세 Dashboard로 들어가고, 그 부문 Attention이 보인다

**Given** 메인에서 본 여신 Attention과 근거가 있다  
**When** 여신 상세를 본다  
**Then** 그 Attention과 근거가 상세에서도 다시 보인다

**Given** 여신이 아닌 사업부문 카드가 있다  
**When** 그 카드를 누른다  
**Then** 해당 부문의 상세 Dashboard는 없고, 그 부문 Attention은 카드 맥락에서 볼 수 있다

#### INVEST

독립: 여신 상세 시드. 협의: 카드 클릭 후 화면 전환. 가치: 주목 이유를 상세에서 이어 본다. 추정·작음: 한 이동. 검증: 위 GWT.

### US-A-04 여신 상세에서 종합수익·기업여신·가계여신을 본다

- **페르소나**: P-SP
- **FR**: FR-2.5, FR-5.1, FR-5.2, FR-5.3, FR-5.4, FR-5.5, FR-5.6, FR-5.7, FR-5.8, FR-5.9, FR-5.10, FR-9.1
- **유형**: 본편
- **E2E**: 3

**스토리**: 종합기획부로서, 여신 현황을 목표 검토에 쓸 수 있을 만큼 이해하기 위해, 종합수익·기업여신·가계여신을 비교 숫자와 Agent 해설로 보고 싶다.

#### 수용 기준

**Given** 여신 상세에 있다  
**When** 핵심 영역을 본다  
**Then** 여신 종합수익, 기업여신, 가계여신이 있고, 중간 깊이 UI이며 지표 목록은 나중에 교체할 수 있다

**Given** 비교가 있는 지표를 본다  
**When** 숫자와 해설을 확인한다  
**Then** 현재값, 전년 동분기 실적, 증감액, 증감률, Agent 요약이 있다. Agent는 해당 화면 실적을 해설한다. 상관·기여를 원인으로 단정하지 않고 “주요 기여 영역”, “원인 후보” 등으로 쓴다

**Given** 여신 종합수익 영역을 본다  
**When** 값을 확인한다  
**Then** 여신 분야 종합수익은 단일 값이고, 위 비교와 Agent 요약이 있다

**Given** 기업여신 영역을 본다  
**When** 지표를 확인한다  
**Then** 잔액, 전년 동분기 대비 증가율, 신규 취급액, 현재 경영목표 대비 Gap, 연체율, 부실률, 예상손실, 신용등급별 분포, 등급별 부도율이 있고, 현재 설정된 기업여신 관련 경영목표를 함께 볼 수 있다

**Given** 가계여신 영역을 본다  
**When** 지표를 확인한다  
**Then** 잔액, 전년 동분기 대비 증가율, 관리목표 대비 현재 수준, 연체율, 부실률, 신용등급 분포(금액·건수), 등급별 부도율, 포용금융 관련 지표(중·저신용자 비중, 관련 공급액 등)가 있다

**Then** 데모 시드는 기업여신 목표 하회, 가계여신 관리목표 상단 근접을 재현한다

#### INVEST

독립: 여신 시드. 협의: 차트·배치. 가치: 수정·신규 목표의 당행 현황 근거. 추정: 한 상세 화면. 작음: 한 화면의 세 영역. 검증: 위 GWT.

### US-AUX-05 공식 도메인을 검색하고 기사를 근거로 확정한다

- **페르소나**: P-SP
- **FR**: FR-7.8, FR-7.9, FR-7.10, FR-7.11
- **유형**: 보조

**스토리**: 종합기획부로서, 검증되지 않은 기사가 자동 근거가 되지 않게 하기 위해, 공식 도메인 검색은 근거로 쓰되 기사는 내가 확정한 것만 근거로 쓰고 싶다.

#### 수용 기준

- 실시간 검색은 지정 공식 도메인만 한다. 기본 대상은 금융위원회, 금융감독원, 기획재정부이며 목록은 설정으로 관리할 수 있다
- 공식 도메인 검색 결과는 Agent 근거로 쓸 수 있다
- 정책 관련 기사는 실시간 검색 근거로 자동 사용하지 않는다. 정부정책/기사 DB 관리 화면에 Agent가 모아 둔 기사 후보가 보이고, 사용자가 근거로 쓸지 확정한 기사만 근거가 된다
- 사용자가 직접 넣은 기사 문서도 확정된 것만 근거로 쓴다
- 데모 시드의 포용금융 언론보도는 이미 확정 상태다 (FR-9.1)

#### INVEST

독립: 검색·확정 시드. 협의: 후보 목록 UI. 가치: 기사 오용 방지. 추정·작음: 검색+확정. 검증: 불릿.
