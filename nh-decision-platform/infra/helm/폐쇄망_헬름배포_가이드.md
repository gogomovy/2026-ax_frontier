# NH NAVI 폐쇄망 Helm 배포 가이드

폐쇄망 쿠버네티스에 `helm install` 로 띄우는 방법입니다. 외부에서 이미지와 차트를 tar 하나로 묶어 반입하고, 내부 Nexus 에 올린 뒤 설치합니다.

```
[외부 · 인터넷 PC]                    [반입]                [내부망]
bundle.sh ─▶ nhdip-closed-1.0.0.tar ─────────▶ push-images.sh ─▶ Nexus 도커 저장소
                                                create-secrets.sh ─▶ Secret(nhdip-secrets)
                                                values-closed.yaml 채우기
                                                helm install ─▶ 지정한 서버(노드)에 기동 · 인그레스 도메인으로 접속
```

- 채울 값은 `values-closed.yaml` 한 파일에만 적습니다. 차트 기본값(`nhdip/values.yaml`)은 고치지 않습니다.
- 비밀값은 어떤 파일에도 남기지 않습니다(§5). 헬름 배포는 `.env` 를 읽지 않습니다.
- 개발 서버의 docker compose 배포(`.env`)는 그대로 둡니다. 개발 서버의 `.env` 를 폐쇄망으로 가져가지 마세요.

## 1. 묶음 구성

| 경로 | 내용 |
|---|---|
| `images/*.tar` | 이미지 tar (`images/images.txt` = 파일 ↔ 이미지 이름) |
| `chart/nhdip-1.0.0.tgz` | 헬름 차트 |
| `values-closed.yaml` | **내부망 값을 채울 파일** |
| `scripts/push-images.sh` | 이미지 tar → Nexus |
| `scripts/create-secrets.sh` | 비밀값 Secret 만들기 · 바꾸기 |
| `VERSION` · `SHA256SUMS` | 태그 · 커밋 · 체크섬 |

들어 있는 이미지:

| 이미지 | 용도 | 비고 |
|---|---|---|
| `nhdip/api:<TAG>` | api · worker | 같은 이미지, 역할만 다름 |
| `nhdip/web:<TAG>` | 화면(Next.js) | 백엔드 주소 `http://api:8000` 이 빌드에 고정 |
| `nhdip/elasticsearch:<TAG>` | 검색(nori 포함) | ES 9.5.4 + nori |
| `nhdip/sso-verifier:<TAG>` | 사내 SSO 티켓 검증 | 벤더 jar 는 들어 있지 않음(§6-4) |
| `pgvector/pgvector:pg16` | PostgreSQL 16 + pgvector | |
| `neo4j:5.26-community` | 그래프 | |
| `berriai/litellm:main-stable` | (선택) 내장 LLM 게이트웨이 | `WITH_LITELLM=1` 일 때만 |

## 2. 외부에서 묶기 (인터넷 되는 PC · 빌드 서버)

필요: Docker(BuildKit), tar, sha256sum, helm(있으면 차트를 `helm package`, 없으면 tar 로 묶음). Windows 는 Git Bash 또는 WSL 에서 Docker Desktop 과 함께 실행합니다.

```bash
cd nh-decision-platform
bash infra/helm/scripts/bundle.sh
# → dist/nhdip-closed-1.0.0.tar
```

| 옵션(환경변수) | 기본 | 설명 |
|---|---|---|
| `TAG` | Chart.yaml `appVersion`(1.0.0) | 자체 이미지 태그. 바꾸면 차트 appVersion 도 같이 맞춰 묶음 |
| `PLATFORM` | `linux/amd64` | 내부 서버가 ARM 이면 `linux/arm64` |
| `WITH_SSO` | `1` | 사내 SSO 검증기 이미지 포함 |
| `WITH_LITELLM` | `0` | 내장 LiteLLM 포함(사내 LLM 게이트웨이가 있으면 필요 없음) |

다시 반입할 때(버전 올림)는 `TAG=1.0.1 bash infra/helm/scripts/bundle.sh` 처럼 태그를 올려 묶습니다.

## 3. 내부에서 Nexus 에 올리기

반입한 tar 를 Nexus 에 접근되는 서버에서 풉니다.

```bash
tar -xf nhdip-closed-1.0.0.tar && cd nhdip-closed-1.0.0
docker login <Nexus 호스트:포트>                        # 예: nexus.example.local:5000
bash scripts/push-images.sh <Nexus 주소>                # 예: nexus.example.local:5000  또는  nexus.example.local:5000/nhdip
```

- 올라가는 이름은 `<Nexus 주소>/<이미지 이름:태그>` 입니다. 예: `nexus.example.local:5000/nhdip/api:1.0.0`.
- 여기 넣은 `<Nexus 주소>` 를 그대로 `values-closed.yaml` 의 `global.imageRegistry` 에 적습니다.
- 도커가 없으면 skopeo 로: `skopeo login <호스트:포트>` 후 `TOOL=skopeo bash scripts/push-images.sh <Nexus 주소>`. HTTP · 사설 인증서 Nexus 면 `SKOPEO_OPTS="--dest-tls-verify=false"` 를 붙입니다.
- (선택) 차트도 Nexus Helm(hosted) 저장소에 두려면:
  ```bash
  curl -u <계정> --upload-file chart/nhdip-1.0.0.tgz https://<Nexus>/repository/<helm-hosted 저장소>/
  helm repo add nhdip https://<Nexus>/repository/<helm-hosted 저장소>/ && helm repo update
  # 이후 설치 명령의 chart/nhdip-1.0.0.tgz 대신 nhdip/nhdip --version 1.0.0
  ```

## 4. 채워야 할 값 — `values-closed.yaml`

`[채우기·필수]` 를 비워 두면 `helm install` 이 무엇이 비었는지 알려 주고 멈춥니다.

### 4-1. 반드시 채울 것

| 항목 | 키 | 예 | 확인 방법 |
|---|---|---|---|
| Nexus 저장소 주소 | `global.imageRegistry` | `nexus.example.local:5000` | §3 에서 push 한 주소와 같게 |
| 띄울 서버(노드) | `global.nodeSelector` | `kubernetes.io/hostname: nhnavi-node01` | `kubectl get nodes` 의 NAME. 라벨로 고르려면 `kubectl get nodes --show-labels` |
| 인그레스 클래스 | `ingress.className` | `nginx` | `kubectl get ingressclass` |
| 접속 도메인 | `ingress.host` | `nhnavi.example.local` | 사내 DNS 에 인그레스 주소로 등록할 이름 |
| TLS 인증서 Secret | `ingress.tls.secretName` | `nhnavi-tls` | §7 에서 만든 tls Secret 이름 |
| 저장소(둘 중 하나) | `persistence.hostPathBase` 또는 `persistence.storageClass` | `/data/nhdip` 또는 `local-path` | `kubectl get storageclass`. 동적 저장소가 없으면 hostPathBase |

- TLS 를 인그레스가 아니라 앞단 L7(로드밸런서)에서 끝내면: `ingress.tls.enabled: false`, `app.publicUrl: https://<도메인>`.
- 저장소를 `hostPathBase` 로 하면 그 서버의 `<경로>/pgdata · neo4j · esdata · files` 에 데이터가 쌓입니다. 서버 디스크가 충분한 곳으로 정합니다.

### 4-2. 내부망 사정에 따라 채울 것

| 항목 | 키 | 언제 |
|---|---|---|
| 이미지 받기 계정 | `global.imagePullSecrets: [nexus-pull]` | Nexus 가 익명 받기를 막을 때(§7) |
| 서버 taint 허용 | `global.tolerations` | 그 서버에 taint 가 걸려 있을 때(`kubectl describe node <노드>`) |
| 프록시 겹 수 | `app.trustedProxyHops` | 인그레스 앞에 X-Forwarded-For 를 붙이는 L7 이 하나 더 있으면 `3` (감사 로그 · 속도 제한의 사용자 IP 기준) |
| 내부 LLM 게이트웨이 | `app.llm.baseUrl` · `app.llm.model` | 최초 기동 때 기본 LLM 연결로 등록(키는 Secret). 비우면 관리자 [LLM 연동]에서 입력 |
| 사내 SSO | `app.ncSso.enabled` · `app.ncSso.assets.hostPath` · `ssoVerifier.enabled` · `ssoVerifier.libs.hostPath` | 사내 SSO 를 쓸 때(§6-4) |
| 사번 로그인 범위 | `app.ncSso.localLogin` | SSO 를 켠 뒤 `admin`(관리자 비상 로그인만) · `none` |
| 알림 메일 | `app.alerts.smtp.*` | 운영 알림을 메일로 받을 때(비밀번호는 Secret) |
| ES 커널 값 | `elasticsearch.sysctlInit: true` | 서버에서 직접 sysctl 을 못 할 때(특권 컨테이너 허용 필요) |
| 저장 용량 | `persistence.*.size` | 기본 PostgreSQL 50Gi · Neo4j 20Gi · ES 30Gi · 파일 100Gi |
| 사내 PostgreSQL 사용 | `postgres.enabled: false` · `postgres.external.host` · `postgres.external.port` · `postgres.user` · `postgres.database` | 차트의 PostgreSQL 대신 사내 DB 를 쓸 때. DB 에 `vector`(pgvector) 확장이 있어야 하고, 비밀번호는 Secret 의 `POSTGRES_PASSWORD` 를 그 값으로 바꿉니다(`create-secrets.sh add POSTGRES_PASSWORD`). 계정에 역할 생성 권한이 없으면 `kubectl -n nhdip patch secret nhdip-secrets --type json -p '[{"op":"remove","path":"/data/APP_DB_PASSWORD"}]'` 로 api 전용 계정을 끕니다 |
| 사내 Elasticsearch · Neo4j 사용 | `elasticsearch.enabled: false` · `elasticsearch.externalUrl` / `neo4j.enabled: false` · `neo4j.externalUri` | 이미 운영 중인 것을 쓸 때. ES 를 아예 안 쓰면 `externalUrl` 을 비워 둡니다(검색은 PostgreSQL 로 축소 동작) |
| CPU · 메모리 | `api.resources` 등 | 네임스페이스 ResourceQuota 가 있을 때(차트 `values.yaml` 의 기본값 참고) |

### 4-3. 그대로 둬도 되는 것

시간대(`Asia/Seoul`), 서비스 이름, DB 사용자 이름(`nhdip`), 인덱스 이름, 프로브, 최초 관리자 사번(`00000001`) 등은 기본값으로 동작합니다. 바꿀 수 있는 전체 목록은 차트 안 `values.yaml` 에 설명과 함께 있습니다.

## 5. 비밀값 — Secret 으로만

DB 비밀번호 · 세션 키 · 암호화 키 · 관리자 비밀번호 · API 키는 `values-closed.yaml` 에도 `.env` 에도 쓰지 않습니다. `create-secrets.sh` 가 무작위 값으로 쿠버네티스 Secret 을 바로 만들고, 값은 디스크나 명령줄 인자에 남지 않습니다. 차트는 이 Secret 을 `secretKeyRef` 로만 읽습니다.

```bash
NS=nhdip bash scripts/create-secrets.sh          # 처음 1회
NS=nhdip bash scripts/create-secrets.sh keys     # 들어 있는 키 이름 보기(값은 안 보임)
```

| 키 | 만드는 방법 | 쓰는 곳 |
|---|---|---|
| `POSTGRES_PASSWORD` · `NEO4J_PASSWORD` · `ES_PASSWORD` | 자동 | 각 DB(처음 기동 때 굳음 — 바꾸지 않음) |
| `APP_DB_PASSWORD` | 자동 | api 전용 DB 계정(DML 만) |
| `SESSION_SECRET` · `CONFIG_ENC_KEY` | 자동 | 세션 서명 · 화면에서 저장한 연결 키 암호화(바꾸면 저장된 키를 못 풂) |
| `BOOTSTRAP_ADMIN_PASSWORD` | 자동(또는 환경변수로 지정) | 최초 관리자 |
| `NC_SSO_VERIFIER_TOKEN` | 자동 | api ↔ SSO 검증기 |
| `LITELLM_MASTER_KEY` · `LITELLM_UI_PASSWORD` | 자동 | 내장 LiteLLM(쓸 때만) |
| `LLM_DEFAULT_API_KEY` | 직접 | 내부 LLM 게이트웨이 키 |
| `OIDC_CLIENT_SECRET` · `ALERT_SMTP_PASSWORD` · `ALERT_WEBHOOK_URL` | 직접 | 쓸 때만 |

`POSTGRES_PASSWORD` 를 직접 정할 때(사내 DB)는 영문 · 숫자만 씁니다. DB 접속 주소(`DATABASE_URL`)에 그대로 들어가기 때문입니다.

직접 넣는 값은 설치 뒤에 추가합니다(입력이 화면에 보이지 않음).

```bash
NS=nhdip bash scripts/create-secrets.sh add LLM_DEFAULT_API_KEY
kubectl -n nhdip rollout restart deploy/api deploy/worker
```

## 6. 서버(노드) 준비

### 6-1. 권장 사양

8 vCPU · 16GB 메모리 · 데이터 디스크 200GB 이상(업로드 양에 따라). 기본 요청량(requests)은 약 2 vCPU · 5.5GB, 상한(limits) 합은 약 15 vCPU · 17GB 입니다.

### 6-2. Elasticsearch 커널 값 (필수)

```bash
sudo sysctl -w vm.max_map_count=262144
echo 'vm.max_map_count=262144' | sudo tee /etc/sysctl.d/99-nhdip.conf
```

서버에 직접 못 하면 `elasticsearch.sysctlInit: true` 로 둡니다.

### 6-3. 노드가 Nexus 를 믿게

노드의 containerd 가 Nexus 에서 이미지를 받을 수 있어야 합니다. HTTP 이거나 사설 인증서인 Nexus 면 노드에 `/etc/containerd/certs.d/<Nexus 호스트:포트>/hosts.toml`(또는 사내 표준 방식)으로 등록합니다. 확인: 노드에서 `crictl pull <Nexus 주소>/nhdip/api:1.0.0`.

### 6-4. 사내 SSO 벤더 파일 (SSO 를 쓸 때만)

벤더 파일은 라이선스 때문에 묶음에 들어 있지 않습니다. 내부에서 받은 파일을 그 서버에 둡니다.

```bash
sudo mkdir -p /opt/nhdip/sso/nc-js /opt/nhdip/sso/libs
# NexessDemonFunc.js · json2.js · jquery-3.5.1.min.js(· jquery-3.5.1.js) → /opt/nhdip/sso/nc-js/
# 벤더 jar(INISAFE Nexess · TicketV3 포함)                              → /opt/nhdip/sso/libs/
sudo chmod -R a+rX /opt/nhdip/sso
```

```yaml
app:
  ncSso:
    enabled: true
    assets: {hostPath: /opt/nhdip/sso/nc-js}
ssoVerifier:
  enabled: true
  libs: {hostPath: /opt/nhdip/sso/libs}
```

SSO 담당 부서에 콜백 주소 `https://<도메인>/backend/auth/nc/callback` 등록(NLS UURL 허용)을 요청합니다. 사용자 PC 에는 NC 에이전트가 떠 있어야 합니다.

### 6-5. hostPath 를 쓸 때

디렉터리는 자동으로 만들어집니다. 소유자는 초기화 컨테이너가 맞춥니다(api 파일 저장소 10001 · ES 1000). 보안 정책(PSA restricted 등)이 root 초기화 컨테이너를 막으면 `api.filesInit: false` · `elasticsearch.chownInit: false` 로 두고 미리 맞춥니다.

```bash
sudo mkdir -p /data/nhdip/{pgdata,neo4j,esdata,files/requests}
sudo chown -R 10001:10001 /data/nhdip/files
sudo chown -R 1000:0 /data/nhdip/esdata
```

## 7. 설치

```bash
cd nhdip-closed-1.0.0
kubectl create namespace nhdip

# TLS 인증서 (인그레스에서 TLS 를 끝낼 때)
kubectl -n nhdip create secret tls nhnavi-tls --cert=<인증서.crt> --key=<개인키.key>

# Nexus 가 익명 받기를 막을 때 — docker login 한 설정 파일로(비밀번호를 명령줄에 쓰지 않음)
kubectl -n nhdip create secret generic nexus-pull --type=kubernetes.io/dockerconfigjson \
  --from-file=.dockerconfigjson=$HOME/.docker/config.json

# 비밀값
NS=nhdip bash scripts/create-secrets.sh

# 설치
helm install nhdip chart/nhdip-1.0.0.tgz -n nhdip -f values-closed.yaml
```

설치 전에 값 점검만 하려면 `helm template nhdip chart/nhdip-1.0.0.tgz -n nhdip -f values-closed.yaml > /dev/null` 을 먼저 돌립니다. 비어 있는 필수 값이 있으면 여기서 알려 줍니다.

### 설치 확인

```bash
kubectl -n nhdip get pods -w                     # api 첫 기동은 마이그레이션 · 시드로 수 분
kubectl -n nhdip logs deploy/api -f
kubectl -n nhdip get ingress
kubectl -n nhdip get secret nhdip-secrets -o jsonpath='{.data.BOOTSTRAP_ADMIN_PASSWORD}' | base64 -d; echo
kubectl -n nhdip exec deploy/api -- python -m nhdip.cli preflight
```

`https://<도메인>` 에서 사번 `00000001` 과 위 비밀번호로 로그인하고 비밀번호를 바꿉니다. 그다음 관리자 [LLM 연동] · [업무 구성] · [조직 · 인사 동기화] 순서로 설정합니다.

관리자 비밀번호를 잊었거나 잠겼으면(8자 이상 · 영문 + 숫자, 입력이 셸 기록에 남지 않게):

```bash
read -rsp '새 비밀번호: ' PW; echo; printf '%s\n' "$PW" | kubectl -n nhdip exec -i deploy/api -- python -m nhdip.cli admin-password 00000001; unset PW
```

## 8. 업그레이드 · 되돌리기 · 삭제

```bash
# 새 묶음(TAG=1.0.1)을 반입 → push-images.sh → 같은 values-closed.yaml 로
helm upgrade nhdip chart/nhdip-1.0.0.tgz -n nhdip -f values-closed.yaml
helm history nhdip -n nhdip
helm rollback nhdip <REVISION> -n nhdip    # DB 마이그레이션은 되돌리지 않음 — 올리기 전에 §9 백업
helm uninstall nhdip -n nhdip              # 데이터(PVC)는 남음(persistence.keep). Secret 도 남음
```

api 는 새 버전이 뜰 때 마이그레이션을 자동으로 적용합니다.

## 9. 백업 (간단)

`make backup`(compose)과 같은 내용 — 업무 DB 덤프 + 업로드 원본. 백업 위치는 서버 밖(사내 백업 저장소)으로 옮깁니다.

```bash
TS=$(date +%Y%m%d-%H%M%S); mkdir -p backup-$TS && cd backup-$TS
kubectl -n nhdip exec statefulset/postgres -- sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > nhdip.dump
kubectl -n nhdip exec deploy/api -- tar -czf - -C /data/files . > filestore.tar.gz
# (내장 LiteLLM 을 쓸 때만) kubectl -n nhdip exec statefulset/postgres -- sh -c 'pg_dump -U "$POSTGRES_USER" -d litellm -Fc' > litellm.dump
# 운영 준비 점검(preflight)의 '백업' 항목에 기록
kubectl -n nhdip exec deploy/api -- env NHDIP_USE_APP_ROLE=0 python -m nhdip.cli record-backup "backup-$TS" "$(du -sb . | cut -f1)"
```

Neo4j 그래프는 PostgreSQL 원장에서 다시 투영하고(관리자 [온톨로지] 재투영), Elasticsearch 색인은 `kubectl -n nhdip exec deploy/api -- python -m nhdip.cli kb-es --rebuild` 로 다시 만듭니다.

## 10. 내부망 점검표

- [ ] 도메인(`ingress.host`)이 사내 DNS 에 인그레스 주소로 등록됨
- [ ] TLS 인증서(사내 CA)를 받아 tls Secret 생성
- [ ] 노드가 Nexus 에서 이미지를 받을 수 있음(§6-3)
- [ ] `vm.max_map_count=262144` (§6-2)
- [ ] 파드에서 내부 LLM 게이트웨이 주소로 나갈 수 있음(방화벽 · NetworkPolicy · 프록시)
- [ ] (SSO) 벤더 JS · jar 를 서버에 배치, 콜백 주소 등록, 사용자 PC 에 NC 에이전트
- [ ] (메일 알림) 파드 → SMTP 서버 접근
- [ ] 네임스페이스 보안 정책이 root 초기화 컨테이너를 허용하는지(아니면 §6-5)
- [ ] 백업 위치 · 주기 정함(§9)

알아둘 점: 화면 글꼴(Pretendard)은 외부 CDN 에서 받는데 폐쇄망에서는 막히므로 시스템 글꼴로 보입니다. 기능에는 영향이 없습니다.

## 11. 주의

- 한 네임스페이스에 이 차트는 하나만 설치합니다. 서비스 이름(`api` · `web` · `postgres` · `neo4j` · `elasticsearch` · `sso-verifier`)은 고정입니다. 웹 이미지가 백엔드 주소를 `http://api:8000` 으로 굳혀 빌드되기 때문입니다.
- api 는 1개로 둡니다(기동 때 마이그레이션 · 시드). web 은 `web.replicas` 로 늘릴 수 있습니다.
- 파일 저장소는 api 와 worker 가 같이 씁니다. 기본(RWO)은 둘이 같은 서버에 있어야 하므로 `global.nodeSelector` 로 서버를 고정합니다. 여러 서버로 나누려면 RWX 저장소(`persistence.files.accessMode: ReadWriteMany`)가 필요합니다.
- Secret 값을 바꾼 뒤에는 해당 파드를 다시 시작해야 반영됩니다(`kubectl -n nhdip rollout restart deploy/api deploy/worker`).
- 차트 서비스는 모두 ClusterIP 입니다. 밖에서는 인그레스(웹)로만 들어옵니다. DB · Neo4j · ES 관리 포트는 열지 않습니다.

## 12. 문제 해결

| 증상 | 원인 · 조치 |
|---|---|
| `helm install` 이 `[필수] …` 로 멈춤 | 메시지의 키를 `values-closed.yaml` 에 채움 |
| `ImagePullBackOff` | `global.imageRegistry` 와 push 주소 불일치 · 노드가 Nexus 를 못 믿음(§6-3) · 받기 계정(`imagePullSecrets`) |
| `CreateContainerConfigError` | Secret(`nhdip-secrets`)이 없거나 다른 네임스페이스 — `create-secrets.sh` 를 같은 `NS` 로 |
| 파드가 `Pending` | 노드 이름 오타 · taint(→ tolerations) · PVC 가 묶이지 않음(storageClass 확인) |
| elasticsearch 재시작 반복 | `vm.max_map_count` 부족(§6-2) · 메모리 부족(`elasticsearch.heap` · resources) |
| api 가 오래 준비 안 됨 | 첫 기동 마이그레이션 · 시드(최대 15분 대기). `kubectl -n nhdip logs deploy/api` |
| 로그인 뒤 바로 튕김 | https 가 아닌 주소로 접속 중인데 Secure 쿠키 — https 로 접속하거나 `app.publicUrl` 확인 |
| 감사 로그 IP 가 모두 같은 주소 | `app.trustedProxyHops` 를 앞단 프록시 겹 수에 맞춤 |
| sso-verifier 준비 안 됨 | 벤더 jar 위치(`ssoVerifier.libs`) · 파일 권한 확인 — `kubectl -n nhdip logs deploy/sso-verifier` |
