## 1. 분석 에이전트 — 팀 DB 활용 (TDB)

- **TDB-01 팀 범위** — 분석 에이전트의 팀 = 요청자 소속 경로에서 가장 가까운 부(DEPT) · 지역본부(REGION)와 그 아래 조직(부서 데이터 책임자 범위와 같은 기준). 경로에 없으면 소속 조직.
- **TDB-02 정형 DB(PostgreSQL) 동적 참조** — 실행할 때마다 ① 명세 입력 자료 ② 팀이 올린 현재 판이 있는 자료 ③ 공통 통합 DB 자료 ④ 온톨로지 연관 자료를 다시 찾고, 명세 제목 · 목적 · 지시와의 관련도 순으로 상위 N개(설정 `analysis_agents.team_context.max_datasets`, 기본 6 · 입력 자료는 항상 포함)를 고른다. 자료마다 보관 기준일 범위 · 기준일 수 · 판 · 행 수 · 소유 · 쓰임(계산 입력 / 참고)을 정리한다.
- **TDB-03 상위 부서 KPI** — 다른 흐름(종기부 경영목표 · 사업부서 · 영업점)이 계산한 지표 가운데 명세가 쓴 KPI와 관련도 높은 지표(기본 6개)의 최근 값 · 직전 값을 함께 본다.
- **TDB-04 근거(Elasticsearch)** — 명세에 근거 설정이 없어도 제목 · 목적으로 근거를 검색한다. 팀 소유 · 소유 없음(전행) · 공통 분류 문서만 쓰고, 하나도 없으면 기존 소유 규칙 범위로 넓히고 그 사실을 남긴다.
- **TDB-05 온톨로지(Neo4j)** — 입력 자료와 연결된 개념 · 지표 · 흐름 관계와, 같은 개념 · 지표를 공유하는 다른 자료(연관 자료)를 찾는다. 개념 키는 근거 검색의 그래프 필터로 쓴다. 그래프 장애면 건너뛰고 '그래프 미사용'으로 남긴다.
- **TDB-06 결과 반영** — ① 분석 전용 에이전트(LLM) 입력에 팀 데이터 요약(자료 · KPI · 관계 · 근거)을 넣는다(수치는 여전히 마커만) ② 보고서 끝에 **'참고한 팀 데이터 (정형 · 근거 · 온톨로지)'** 절 — 정형 자료 표 · 상위 KPI 표 · 근거 문서 표 · 온톨로지 관계 표 ③ 의견 근거에 '당행 Data'(계산에 쓴 자료 · 판 · 기준일)를 붙여 근거 범주 검증이 실제 상태를 반영한다.
- **TDB-07 자동 재실행** — 팀이 새 자료를 반영하거나(소유 조직이 팀 범위) 공통 통합 DB 자료가 바뀌면 그 팀 분석 에이전트가 다시 돈다(입력 자료가 아니어도). 조건은 승인 때 만든다(`team` · `common` 조건).
- **TDB-08 빌더 카탈로그** — 자료 목록에 '우리 팀 · 공통 · 전행 · 다른 부서'를 표시하고, 정제(규칙 · LLM)는 우리 팀 > 공통 > 그 밖 순으로 고른다.
- **TDB-09 미리보기** — 미리보기도 같은 '참고한 팀 데이터' 절을 보여 준다(저장 없음).

## 2. 변경 감지 · 에이전틱 워크플로 (AGW)

- **AGW-01 감지 대상** — 자료 반영 · 되돌림 · 삭제, 문서 반영, 정의서 변경, 판정 규칙 변경, 경영목표 확정 · 수정 · 되돌림 · 삭제, 설정 변경, **상위 흐름 결과(지표) 변경**, 공통 통합 DB 자료 · 문서.
- **AGW-02 실행 전 영향 판단(판단 에이전트 `impact_assessor`)** — 디스패처가 이벤트마다 영향받는 흐름과 이유(명시 조건 · 계보 · 팀 · 공통 · 상위 흐름 · LLM 경로)를 정하고 결정 기록에 남긴다(`ops.agent_decision`, 결정 `impact`). 같은 구획의 현재 판과 같은 파일(해시 · 행 수 같음)을 다시 반영한 이벤트는 '변경 없음 — 다시 계산하지 않음'으로 판단한다.
- **AGW-03 상위 → 하위 결정론 전파** — 흐름이 성공하고, 다른 흐름이 참조하는 지표 값이 바뀌면 `metrics.changed` 이벤트를 낸다. 디스패처는 그 지표를 참조하는 흐름(분석 에이전트 포함)을 다시 계산한다(LLM 없이도). 그 이벤트 뒤에 이미 시작한 하위 실행이 있으면 다시 넣지 않는다. 순환 · 최대 연쇄 깊이는 기존 안전장치(`orchestrator.policy.max_chain`).
- **AGW-04 공통 DB 전파** — 공통 자료 이벤트는 계보 흐름 + 공통 조건을 가진 분석 에이전트로, 공통 분류 문서는 근거 검색 노드가 있는 모든 업무 흐름으로 간다(서술 갱신 여부는 플래너가 판단).
- **AGW-05 실행 순서** — 상위 흐름이 대기 · 실행 중이면 하위는 기다린다(기존 오케스트레이터 `gate`). 
- **AGW-06 자동 주기** — 업무 흐름은 업무 구성 파일의 정기 실행(매일 06:00~06:30, 워커 20초 주기 평가, 놓치면 1회 실행). 분석 에이전트는 승인 때 정기 실행을 정하지 않으면 기본값(설정 `analysis_agents.default_cron`, 기본 `40 6 * * *` · 빈 값이면 없음).
- **AGW-07 수동 실행** — 업무 화면 '분석 다시 실행', 관리자 [자동 실행 · 변경 감지]의 흐름별 '지금 실행'.
- **AGW-08 업무 화면 상태 표시** — 분석 보고서 화면에 자동 갱신 조건(자료 변경 시 · 매일 HH:MM · 상위 지표 변경 시 · 공통 DB 변경 시), 다음 정기 실행 시각, 마지막 갱신, **반영 대기 · 실행 중(원인 요약)** 을 보여 준다. 대기가 끝나면 화면을 새로 고친다.
- **AGW-09 관리자 [자동 실행 · 변경 감지]** — 흐름별 감지 조건 · 상위 흐름 · 정기 실행(다음 시각 · 마지막 발화) · 대기/실행 상태 · 마지막 실행, 최근 영향 판단 기록, 감지 정책 요약(디바운스 · 최대 연쇄 · LLM 경로 이벤트 · 사람 승인 대상).
- **AGW-10 안정성** — 상태 조회는 읽기 전용. 새 이벤트 · 판단 기록 실패가 디스패치 · 실행을 멈추지 않는다.

## 3. 업로드 기준일 · 메모 · 날짜별 비교 (UPV)

- **UPV-01 구분 기준** — 같은 자료의 판을 구분하는 것은 **기준일(× 소유 구획: 영업점은 영업점마다)** 이다. 메모는 설명(보관 · 표시), 시행일은 문서 전용. [자료 올리기]에 이 규칙을 적는다.
- **UPV-02 반영 미리보기** — 요청 때 이 파일이 '새 기준일로 추가'인지 '같은 기준일 vN 교체'인지, 파일 안 기간, 이미 있는 기간과 겹치는지(최근 반영 우선), 같은 파일인지 계산해 요청 결과 · 검토 카드에 보여 준다.
- **UPV-03 기준일 불일치 차단** — 기준일 열이 있는 자료에서 입력한 기준일의 달이 파일 기간에 없으면 요청을 받지 않는다(다른 달 판을 잘못 교체하지 않게).
- **UPV-04 기준일 열 없는 자료** — 계산은 구획마다 가장 늦은 기준일 판만 쓴다(날짜별 판이 합쳐져 중복 집계되지 않게). 화면에 '날짜별 비교에는 기준일 열이 필요' 안내.
- **UPV-05 같은 파일 재업로드** — 같은 구획 현재 판과 해시 · 행 수가 같으면 경고하고, 반영해도 재계산하지 않는다(AGW-02).
- **UPV-06 메모 · 요청자 보존** — 판에 요청자 메모(`memo`)와 요청자(`requested_by`)를 승인 기록(`note`)과 따로 저장한다(예전 요청은 이전 시 채움).
- **UPV-07 보관 기준일 목록** — [자료 올리기]에서 대상 자료를 고르면 보관 중인 기준일(판 · 행 · 메모 · 반영일 · 소유)을 보여 준다.
- **UPV-08 기간 값 정규화** — 행의 기준일 값을 날짜로 맞춰 겹침을 판단한다(202607 과 2026-07-31 은 같은 기간).
- **UPV-09 날짜별 비교 분석** — 분석 에이전트 카탈로그에 자료의 보관 기간을 주고, 정제 지시에 `$latest-1`(직전 기간) · `$latest-12`(전년 동기) · `$earliest`를 안내해 전월 대비 지표를 만들 수 있게 한다.

## 4. 관리자 메뉴 (ADM2)

- **ADM2-01 묶음 재구성** — 업무 순서대로 7묶음: 관리자 홈 / 데이터 반영 / 에이전트 · 자동화 / 운영 현황 / 실행 기록 · 품질 / 계산 · 설정 / 사용자 · 권한.
- **ADM2-02 접힘** — 지금 보는 화면이 든 묶음만 펼치고, 접힌 묶음 머리에 항목 수 · 처리 대기 건수.
- **ADM2-03 메뉴 찾기** — 사이드바 위 입력으로 메뉴 이름을 거른다.
- **ADM2-04 이전** — 1회. 관리자가 묶음을 바꾸지 않은(이전 기본 묶음인) 화면만 옮긴다.

## 5. 빈틈 개선 (GAP)

- **GAP-01** 분석 에이전트 의견의 '근거 존재' 검증이 항상 실패 → TDB-06 ③.
- **GAP-02** 검증 항목이 없는 의견에 '검증 0/0 통과' 표시 → 표시하지 않는다.
- **GAP-03** 분석 에이전트의 상위 흐름 조건이 승인 때 사본 → AGW-03.
- **GAP-04** 요청 경로 판의 올린 사람이 승인자 → UPV-06.
- **GAP-05** 공통 DB 이벤트 표시 무시 → AGW-04.
- **GAP-06** 같은 파일 재반영도 전체 재계산 → AGW-02 · UPV-05.
- **GAP-07** 기준일 열 없는 자료 중복 집계 → UPV-04.
- **GAP-08** 기간 값 형식 차이로 같은 기간이 겹쳐 들어감 → UPV-08.

## 6. 변하지 않는 것

- 기존 업무 흐름(종기부 · 사업부서 · 영업점 · 영업본부)의 계산 결과 · 화면 수치. (UPV-04 · UPV-08 은 날짜별 판이 쌓였거나 형식이 섞인 경우에만 결과가 바로잡힌다.)
- 기존 트리거 · 정기 실행 · 사람 승인 · 연쇄 안전장치.
