- 단가 `llm.pricing` 을 원/1천 토큰 · 1,400원/USD 시뮬레이션 가정으로 로컬 DB 에 입력(sonnet 2.8/14.0, haiku 1.4/7.0, opus-5 7/35, titan 0).

### 2.3 ③ 사업부서 · 영업점 컬럼 정의서 (B.38)

결정:
- Q79 표 코드 부서 접두(`RISK_T01` · `BRANCH_T02`), 종기부는 T01 유지. mart 이름 `risk_t01`. 설정 `contracts.dept_prefix` 에 `사업부서: risk` 추가. S 시트의 두 번째 토막('기업여신' 등)은 주제이므로 정의서 T 시트의 부서를 따른다.
- Q80 다행 표는 행 생성기(`contracts/rows.py`, 설정 `contracts.row_builders`). 파생 값은 커널 `execute`. 단위 환산(충당금 백만원→원, 익스포저 억원→원 — 커널 LINEAR). PSI 비중은 데이터셋 `obs_share`(화면 0.082 와 일치; 처음엔 건수 기반으로 0.0814 가 나와 T01 과 T02 가 어긋났음 → `share_col` 파라미터로 선택 가능하게). 모니터링 상태 라벨 '상한초과 · 주의(상한내관리) · 일상'(시뮬레이션 가정).
- Q81 원천 없는 컬럼은 미연결(전년말 · 연체원장 · 상품↔Pool 매핑 · 재무→신용등급 매핑이 필요한 예상등급류 · 방법론 임계값 · 가감점 · 예상 순수익). 영업점 T02 의 서술 · HTML 은 ALL 행에만(80행 반복 방지, `rows_where`).
- Q82 S01~S03 은 적재하지 않고 원천 컬럼 존재만 검사, S99 는 문서 DB 에서 적재(영업점 S99 는 영업점 노출 허용 문서만). 정의서 연결 변경 시 그 표를 적재하는 워크플로가 계보로 재실행(`lineage:contract`).

구현 중 만난 문제와 해결:
- 생성한 행 생성기를 실데이터로 돌려 보니 정상 → 시드 JSON 생성 시 `docker compose run` 에 `-T` 가 없어 "the input device is not a TTY" → `-T` 추가.

- BRANCH_T03 권고 문장이 '서술 없음' → 보고서 절이 kv 블록이라 글을 못 뽑음 → `resolve_binding` 이 kv 블록도 읽게.

## 5. 판단 근거로 남겨 둘 것 (다시 고민하지 않도록)

- **원천이 없는 컬럼에 값을 만들지 않음** — 정의서 '추가 필요 · 임의 확정 금지' 를 따른다.

- **렌더링은 결정론** — LLM 이 화면 구성을 매번 정하면 형식 오류 · 수치 왜곡 위험. LLM 은 정제 단계에서 구성을 제안만.
- **기존 분석은 표시 단계만 공유** — 계산 노드 · 탭 산출물 · 골든셋 · 정의서 대조를 깨지 않는다. 탭 목록은 API 에서 합친다(산출물 경합 없음 — `analysis_tabs` 항목에 id 가 없어 3방향 병합이 목록 단위).
- **미리보기에서 LLM 을 부르지 않음** — 저장점 되돌림이라 LLM 호출 기록(예산 집계)도 되돌려져 비용 한도를 우회할 수 있다. 의견은 승인 후 실행에서.
- **요청 글은 전용 에이전트 시스템 프롬프트 안에서도 구분자(`<<자료>>`) 안** — 승인 후에도 인젝션이 지시가 되지 않게. 본문 글 블록에 숫자 금지(검증되지 않은 수치 차단).
- **영업점 공간은 분석 만들기 없음** — 지점 범위 실행(B.47)과 겹치면 지점마다 LLM 비용이 늘어난다(Q98). 필요하면 설정 `analysis.spaces.branch.builder`.
- **`Button` 이 data · aria 속성을 버리던 문제** — TSX 는 하이픈 속성을 타입 오류로 잡지 않는다. E2E 에서 발견, `Button` 이 나머지 속성을 넘기도록 수정.

바뀐 파일(주요): `api/{admin_home,db_uploads,analysis_spaces,analysis_agents}.py`(신규) · `api/{screens,reports,menu_counts,admin_core,admin_data}.py` · `analysis_registry.py` · `analysis_agents/{spec,refine,render,lifecycle}.py`(신규) · `workflow/analysis_nodes.py`(신규) · `data/datasets.py`(`check_file`) · `reports/model.py`(`metrics` 블록) · `migrations/versions/0012_phase_c.py` · `models/{cfg,runtime}.py` · `seed/{defs_core,run}.py` · 웹 `styles/tokens.generated.css` · `tailwind.config.ts` · `components/ui/{StatCard,Layout,primitives}.tsx` · `components/charts/Bars.tsx` · `components/admin/{kit,ValueView}.tsx` · `components/analysis/*` · `components/knowledge/*` · `components/layout/{AppShell,PageHeader}.tsx` · `app/admin/{page,settings,monitor,uploads,analysis-agents,…}` · `app/analysis/*` · `app/knowledge/upload` · `apps/e2e/{e2e,a11y}.mjs` · 시험 `tests/test_integration.py`(+3).

- **Esc 는 문서 단위** — 확인 대화상자의 Esc 를 대화상자 요소에만 걸면 초점이 아직 밖에 있을 때(열린 직후) 닫히지 않았다(E2E 에서 발견). 문서 keydown(capture)으로 바꾸고 초점은 열리자마자 [취소]로.

### 8.2 Phase H (2026-10-13) — 3-way 검색 구성
요청: "PostgreSQL · Elasticsearch 의 키워드 · 의미 분할(벡터화) · Neo4j 3-way 구성이 최고의 방향이면 요구사항 · 설계 · 태스크를 쓰고 수행, 다른 세션이 만든 AI 어시스턴트(PostgreSQL 벡터)도 3-way 로". 앞선 대화에서 '팀별 컬렉션은 pgvector 에서도 논리 컬렉션(컬렉션 열 + 사전 필터)으로 된다', '문서 원문 검색은 ES 이점이 더 크다' 를 설명한 뒤의 지시.
판단 근거:
- **3-way 를 추천안으로 채택(Q130)** — 단, ES 를 원장으로 두지 않는다. 권한 기준(사용자 · 조직 · 컬렉션 · 문서 등급)과 게시 트랜잭션이 PostgreSQL 에 있어 판정은 PostgreSQL 이 하고 ES 는 후보만 찾는다(재확인). 임베딩 값도 PostgreSQL(색인 재생성 때 모델을 다시 부르지 않음 — Q131).
- **다른 세션 작업 위에서** — 다른 세션이 `feat/nh-decision-platform` 에 ES 선택 백엔드 · AI 어시스턴트 이름 변경까지 올려 둔 `b62407d` 에서 별도 작업 트리(`%TEMP%\nhdip-3w`, 브랜치 `feat/search-3way`)로 시작했다. 그 세션의 ES 코드(분석 결과 색인 · 차단기 · 재확인)는 그대로 두고 문서 색인 · 엔진 선택 · 사전을 더했다.
- **nori 가 고유명사의 글자를 버림** — 로컬 ES `_analyze` 에서 `새희망홀씨대출` → 희망 · 홀씨 · 대출, `햇살론뱅크` → 햇살 · 뱅크. 사전을 따로 관리하지 않도록 온톨로지 별칭에서 자동 생성하고(Q134), 나눌 수 없는데 기본 분석이 잘 다루는 낱말은 넣지 않는다(통째로 넣으면 '여신' 질문이 '기업여신' 을 못 찾게 됨).
- **기본값 auto(Q132)** — ES 없이(로컬 · 시험 · 장애) 띄워도 그대로 동작해야 한다. CI pytest 는 ES 없이(가짜 전송 시험) · CI e2e 는 ES 포함 compose 스택으로 3-way 를 실제로 돈다(`kb-es --check` · `E2E_EXPECT_ES=1` · 골든셋).
- **메모리** — 이 PC 의 커밋 한도가 남지 않아 ES(768MB) 가 뜨지 않았다. 앞선 작업들이 남긴 Kiro 터미널 셸(powershell, 자식 없음) 125개(약 18GB 커밋)가 원인이라 정리했다.
### 8.3 Phase I · J (2026-10-13) — 하드코딩 제거(실제 파일 업로드) · 업로드 자료 삭제
요청: ① "목데이터로 들어가 있는 것을 기존 데이터 정의 · 자료로 그럴싸한 실제 엑셀 등으로 만들고 실제로 업로드해서 잘 나오는지 확인, 하드코딩을 없앤다" ② "데이터 관리자가 기존 업로드 자료를 삭제할 수 있는 권한, 삭제하면 벡터 DB · Neo4j 에서도 지워지게". 지시: 멈추지 말고 끝까지, EC2 배포 금지.
판단 근거:
- **시드는 정의만(Q135)** — 시드가 행을 직접 넣으면 어댑터 · 매핑 · 보안 · 품질 검사를 건너뛰어 '업로드해서 잘 나오는지' 를 확인할 수 없다. 시연 자료는 같은 업로드 경로(HTTP · TestClient · CLI 는 같은 적재 함수)로 올린다. 운영 DB 의 예전 시드 자료는 지우지 않는다(되돌릴 수 없음) — 지우려면 새 삭제 기능으로.
- **화면 틀 + 서식 문구(Q138)** — 워크플로는 수치를 id 로만 갱신하고 문구 · 기간 · 판정 근거는 그대로 두었다(하드코딩이 남는 원인). 문구를 `xxxTpl` 표식으로 두고 `build_views` 가 모든 산출물의 수치로 렌더한다. 서술(LLM 담당)은 수치 마커만.
- **하드코딩 판정은 교란 검사(Q139)** — 균일 배율은 비율 · 증가율이 그대로라 판정이 틀린다(점검 중 확인). 셀마다 다른 비율 · 구간별 행 제외(3~25%) · 등급 이동 패키지를 두 벌 올려 두 번 모두 그대로인 자리만 후보로 본다. 남은 자리는 0 · 구성비 합계 100% · 1% 미만 표 칸(차주 1명 ≈ 0.6%) · 규칙값 · 기획 입력 · 건수 기반처럼 이유가 있는 것만 예외 목록(경로 · 이유)으로 — 처음 184곳 → 0.
- **값 변화는 받아들임** — 모형 판정 · 가계 연말 추정은 목데이터 문구와 다르지만 계산 근거가 있는 값이 맞다(PRIN-05). CET1 · 소매 연체율은 원천이 없어 '미제공' 으로 둔다(지어내지 않음).
- **삭제는 내용 삭제 + 메타 표시(Q145)** — 버전 행까지 지우면 다음 업로드가 같은 버전 번호를 다시 써 감사 기록 · 그래프 키(`코드:v번호`)가 섞인다. 행 · 본문 · 청크(임베딩) · 원본 파일은 지우고 '삭제됨' 기록만 남긴다.
- **외부 저장소는 작업 큐(Q146)** — 원장(PostgreSQL)은 같은 트랜잭션, Elasticsearch · Neo4j 는 커밋 뒤 바로 한 번 + 워커 재시도. 요청 안에서 직접 지우면 저장소 장애 때 요청이 실패하거나 원장과 어긋난다. 같은 문서 코드가 다시 올라오면 그래프 삭제는 건너뛴다(새 문서 노드를 지우지 않게). 재투영 · 색인 동기화가 이중 안전장치.
- **권한은 관리자 + 지정(Q143)** — 되돌릴 수 없는 작업이라 관리자 전원이 아니라 지정된 데이터 관리자만. 지정 · 해제도 데이터 관리자만, 마지막 한 명은 해제 불가.
- **계보 과잉 실행** — 위험 대시보드 데이터 품질 표를 두 워크플로가 같은 자료 목록으로 바인딩해, 충당금만 올려도 모형 모니터링이 돌았다(기존 시험이 잡음). 자기 자료만 `dataset`, 다른 쪽 자료는 `ref_dataset`(표시만)으로 나눴다.
