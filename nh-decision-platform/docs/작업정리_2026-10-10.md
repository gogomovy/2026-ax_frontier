### 화면에서 달라진 점
- **보고서**
  - "보고서로 내려받기"가 형식 메뉴(PDF · 한글 HWPX · 한글 HWP · HTML)로 바뀌었습니다.
  - "분석 다시 실행" 버튼을 누르면 단계별 진행이 실시간으로 보이고, 끝나면 화면이 새로 고쳐집니다.
- **근거**
  - "원본 열기"로 원본 문서 뷰어가 열리고, 인용된 면 · 인용문이 표시됩니다.
  - 근거는 공식성 · 시점 · 의미 · 개념 연결로 순위를 매기고, 외부 정책 · 내부 경영방향을 각각 1건 이상 보여줍니다.
  - 부서한정 문서는 소유 부서 사용자에게만 보입니다.
- **경영목표 설정**
  - 추천 범위 · 문구 · 산출 근거는 계산 커널이 만듭니다.
  - 상한을 넘는 값을 넣으면 경고가 뜨고, 사유를 적어야 확정됩니다.
  - 목표 시트에서 변경 이력(처리자 · 사유)과 변경 영향(다시 계산될 지표 · 화면 · 재검토할 방안)을 봅니다.
- **수행방안**: 가이드를 규칙 조건으로 고르고 판정 근거를 표시합니다(예: 충당금 비중 증가 1.19%p > 0 → 소매 풀 집중 모니터링).
- **AI Attention**: 순위 점수와 근거를 규칙 · 지표로 계산합니다(예: 기업여신 92.4점).
- **로그인**: SSO 를 설정하면 SSO 버튼이 생깁니다.
- **관리자**
  - 새 화면: [요청 추적] · [골든셋 평가] · [운영 알림 · 비용].
  - 데이터셋 업로드는 원본 보고서 양식을 자동 인식합니다.

- 다지점 LLM 사용 상한(Q98) — 지점이 많아도 실행마다 LLM 을 쓰는 지점은 5곳까지(설정 `narrate_max`), 서술이 오래된 지점부터 돌아가며 갱신합니다. 나머지 지점은 수치 · 화면은 그대로 계산하고 문장만 다음 차례까지 유지합니다
- 지점을 고르면 화면 사이 이동(다음 단계 · 득점표 알림 · 사이드바 메뉴)에도 그 지점이 유지됩니다. 브라우저 시험이 가상 지점을 만들어 선택 상자 · 이동 · 접근성까지 확인하고 원래대로 되돌립니다
- 사내 LLM 게이트웨이 연결 상태의 업로드 시험(B.48) — 34개 판정 모두 통과. 시험 중 찾은 두 가지를 고쳤습니다: 영업점처럼 변화 후보가 많을 때 LLM 판단이 시간 초과로 규칙으로 바뀌던 문제(출력 길이에 맞춰 대기 시간 · 출력 상한을 늘림), 문서의 정책 기조를 '확대' 처럼 한글로 답하면 버려져 '부분 추출' 로 남던 문제(같은 뜻의 코드로 맞춤). 이제 문서 2건 모두 '추출 완료' 입니다
- 남은 확인: LLM 연결 상태의 업로드 시험 · 운영(EC2) DB 반영 후 보강 적용 확인(`docs/남은작업_2026-10-11.md` 0.1)

## 업무 자료 올리기 · 분석 에이전트 · 관리자/모니터링 정리 · 화면 다듬기 (Phase C · 2026-10-12)

- **업무 자료 올리기** — [데이터베이스 > 자료 올리기]에서 업무 부서가 정형 자료(기존 자료의 새 버전)나 문서를 직접 올립니다. 올리는 즉시 보안 · 형식 · 품질 검사 결과(행 수 · 통과/주의/실패)를 보여 주고, 품질 실패 자료는 요청하지 않습니다. 요청은 '승인 대기' 로 남고(화면 수치 그대로), 관리자가 [자료 승인]에서 승인하면 관리자 직접 업로드와 같은 경로로 반영 · 재계산됩니다. 반려는 사유를 남기고 요청자 '내 요청' 에 보입니다. 기본 권한: 종합기획부 · 신용리스크관리부(관리자 [화면 권한]에서 조정)
- **분석 에이전트(부서 맞춤 분석)** — [분석 만들기]에서 도메인 지식 · 하고 싶은 분석을 글로 적으면
  ① 정제 에이전트가 데이터 · 계산식 · 표 · 보고서 구성 · 의견 지시로 정리(허용된 데이터 · 계산식만, 숫자는 계산 커널) → 확인 · 수정 → 미리보기(실제 계산, 저장 안 함) → 승인 요청
  ② 관리자가 [분석 에이전트]에서 승인하면 그 분석 전용 에이전트 · 지표 · 워크플로가 만들어지고, 자료가 바뀌거나 정해진 주기마다 계산 → 전용 에이전트가 판단 · 의견 작성(수치는 마커만, 검증 통과분만 게시) → 범용 렌더링이 보고서 조립
  ③ 결과는 부서 분석 화면에 '맞춤' 탭으로 나타납니다(신용리스크 [분석 결과], 종합기획부 [분석 보고서]). 기존 분석 보고서와 같은 화면 · 내려받기를 씁니다. 관리자는 일시 중지 · 재개 · 폐기, 요청자는 고쳐서 새 버전 요청
- **부서 분석 공간** — 부서 분석 화면 목록을 설정(`analysis.spaces`)으로 관리해 새 부서는 화면 등록 + 설정만으로 추가(코드 변경 없음). 기존 신용리스크 · 영업점 분석은 계산은 그대로, 표시만 같은 구성 요소
- **관리자 화면 정리** — 메뉴를 6묶음(관리자 홈 · 사용자와 권한 · 데이터와 지식 · AI · 에이전트 · 계산과 규칙 · 운영 모니터링)으로, 사이드바에서 묶음 접기. 관리자 홈에 처리할 일(가입 · 자료 · 분석 · 실행 승인 대기, 경고 알림)과 시스템 상태. 규칙 · 워크플로 · 지표 · 설정 · 온톨로지 · 데이터셋 화면은 요약 카드 · 찾기 · 읽기 쉬운 값 보기, 원본 JSON 은 '고급' 접기 안
- **운영 모니터링** — [운영 개요]에 시간대별 실행 상태 · LLM 호출 · 이벤트 그래프(그래프마다 '표로 보기'), 워크플로별 성공률 · 소요, 느린 노드, 에이전트별 토큰, 최근 실패 · 알림. [에이전트 실행]은 노드 타임라인 · 요약 카드
- **디자인 시스템** — 색을 모두 디자인 토큰으로(옅은 배경 · 글자 대비 · 차트 팔레트), 공통 구성 요소(요약 카드 · 위치 표시 · 빈 상태 · 고급 접기 · 막대 그래프), 모바일 메뉴 대화상자(포커스 가두기 · Esc)

## 사용자 흐름 기준 UI/UX 개선 — 파일 먼저 올리기 · 관리자 첫 화면 · 확인 대화상자 (Phase E · 2026-10-13)

- **관리자 첫 화면** — 관리자는 로그인하면 [관리자 홈]으로 가고, 사이드바는 관리 묶음이 먼저(가입 · 자료 · 분석 승인 대기 건수 배지), 업무 화면은 '업무 화면 · 부서' 접힘 묶음으로 뒤에 둡니다. 사이드바 선택 표시는 하나만, '시뮬레이션 데이터' 표시는 현재 자료가 실제로 시뮬레이션일 때만 보입니다.
- **확인 대화상자** — 브라우저 기본 확인 · 입력 창을 모두 앱 대화상자로 바꿨습니다(관리자로 역할 변경 · 소속 · 중지 · 가입 반려 · 비밀번호 재설정 · 조직 이동 · 이름 · 확정 업로드 · 강제 확정 · 강제 승인 · 되돌리기 · 분석 폐기 · LLM 키 삭제). 초점은 [취소], Esc 로 닫힙니다.
- **안내 · 표기** — 권한 없음 화면은 어느 화면인지 · 누구에게 요청하는지를 보이고, 없는 화면은 내 첫 화면으로 안내합니다. 실패 알림은 색 · 아이콘 · 읽기 방식이 성공과 다릅니다. 업무 화면의 'Agent' · 'AI Attention' 은 'AI' · 'AI 주목 사항' 으로, 관리 화면 상태 배지는 한국어(영어 코드는 마우스를 올리면)로 바꿨습니다.

## 온톨로지 구성 시각화 — 3D 군집 지도 · 구조도 · 표 (Phase G · 2026-10-13)

- **원장 기준 지도** — 관리자 [온톨로지] 첫 탭 '구성 지도' 는 PostgreSQL 원장에서 Neo4j 투영과 같은 코드로 개체 · 관계를 모아 그립니다. Neo4j 가 꺼져 있어도 구성과 요약 수치(개체 · 관계 · 군집)가 그대로 보입니다(지금까지는 Neo4j 가 없으면 아무것도 보이지 않았음).
- **3D 군집 지도** — 점 = 개체(클래스별 색 · 연결이 많을수록 크게), 선 = 관계. 서로 많이 엮인 개체를 군집(Louvain)으로 묶어 공간에 모아 두고 군집 이름(주 클래스 · 대표 개체)을 띄웁니다. 끌어서 회전 · 휠로 확대 · 자동 회전(움직임 줄이기 설정이면 꺼짐) · 2D 평면 전환.
- **찾기 · 상세** — 이름으로 찾거나 점을 누르면 그 개체의 클래스 · 군집 · 출처(데이터셋 · 문서 추출 등) · 추출 방식 · 근거 문장 · 관계별 이웃이 옆에 나오고, 이웃을 눌러 따라갈 수 있습니다. 범례로 클래스를 숨기거나, 군집을 눌러 그 묶음만 밝게 볼 수 있습니다.
- **구조도 · 표** — 클래스와 관계 유형을 실제 개수와 함께 한 장으로 보는 구조도, 같은 내용을 글로 보는 표(군집 · 관계 구조 · 클래스).
- 벡터 저장소(Elasticsearch · Milvus) 전환 요청은 다른 작업 브랜치(`feat/ask-knowledge-hybrid-rag`)에서 Elasticsearch 검색 백엔드로 이미 진행 중이라 이번에 하지 않았습니다(같은 검색 코드를 두 갈래로 바꾸면 충돌). 로컬에서 확인한 Elasticsearch 동작은 설계 §23.6 에 남겼습니다.

## 3-way 검색 구성 — PostgreSQL 원장 · Elasticsearch 키워드/의미 · Neo4j 그래프 (Phase H · 2026-10-13)

사용자 지시: 검색을 PostgreSQL · Elasticsearch(키워드 · 의미 벡터) · Neo4j 3-way 로, AI 어시스턴트(다른 작업 브랜치에서 만든 것 — 분석 결과만 선택적으로 ES)도 이 구성으로. 요구사항 §24(TW-01~10) · 설계 §24 · Q130~Q134 · tasks Phase H.

- **문서 색인**: 현재 판 문서 청크를 `nhdip-doc-chunk`(id `<출처>:<청크 id>`, 분류 · 문서 코드 · 부서한정 등급 필드)로. 워커 1분 동기화(새 판 → 이전 판 청크 삭제), 아직 못 올린 새 청크는 PostgreSQL 보충. 검색 결과는 PostgreSQL `doc_filter` 로 재확인(부서한정 · 분류 · 이전 판이 새지 않음).
- **AI 어시스턴트**: 분석 결과 · 문서 키워드 · 의미 채널을 ES 에서(그래프는 Neo4j + 개념 태그). 응답 `retrieval.engines` · 답 아래 '검색 Nms · Elasticsearch · 그래프 Neo4j'.
- **워크플로 근거 검색**(`hybrid_search`): 같은 문서 색인 · 분류 · 개념 경로 문서 조건, 재확인 · 보충 · 폴백. 노드 결과 `searchEngine`. 문서 청크도 모델 교체 시 재임베딩 · 같은 모델 벡터만 비교.
- **한국어 분석**: nori + 온톨로지 별칭으로 만든 사용자 사전(기본 nori 가 '새희망홀씨' 의 '새' · '햇살론' 의 '론' 을 버리는 문제). 사전 · 매핑 판이 바뀌면 색인 자동 재생성.
- **표준 구성**: compose 기본 서비스 elasticsearch, 검색 설정 기본 `auto`(기존 DB 1회 보강), `.env.example` ES_URL · ES_USER · ES_DOC_INDEX, `ensure-env` ES_PASSWORD, `check-host` vm.max_map_count, CI e2e(sysctl · `kb-es --sync` · `kb-es --check` · `E2E_EXPECT_ES=1`).
- **운영**: CLI `kb-es [--sync|--rebuild|--check]`, 운영 점검 `search_backend`, 관리자 3-way 구성 카드.
