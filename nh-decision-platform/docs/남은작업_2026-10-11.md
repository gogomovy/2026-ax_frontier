## 1. 프로젝트 개요 (작업 전에 꼭 알아야 할 원칙)

- 목적: 농협은행 종합기획부(경영목표) · 신용리스크관리부(모형 모니터링 · 포용금융 리스크) · 영업점(업적평가 영업 가이드) 업무를 데이터 → 계산 → 에이전트 판단 · 서술 → 화면으로 자동화하는 플랫폼.
- **수치는 계산 커널만 만든다.** LLM 은 무엇이 중요한지 판단하고 문장을 쓰지만 숫자는 `[[fig:ID]]` 마커로만 참조한다(CALC-08). 질의 패널은 답변의 숫자가 확정 수치 · 도구 결과에 있는지 검사한다(numeric_provenance).
- **하드코딩 금지.** 값 · 기준 · 매핑은 관리자 화면에서 바꿀 수 있는 규칙(`cfg.rule`) · 설정(`cfg.setting`) · 연결(컬럼 정의서 binding) · 지표 정의에 둔다. 수치 가정은 규칙에 두고 "시뮬레이션 가정" 이라고 표시한다.
- **작업 합의(`.kiro/steering/working-agreement.md`):** 확인이 필요한 질문은 추천안으로 결정하고 멈추지 않는다. 결정은 요구사항 §16.4 결정 기록 · §16.5 미결 표에 "추천안 적용" 과 되돌리는 방법을 함께 적는다. 파괴적 작업(데이터 삭제 · 운영 배포 · 권한 해제)만 사용자 확인.
- 데이터 원본(`data/` 폴더 — 시나리오 정의 엑셀 · PDF)은 **저장소에 올리지 않는다.** 종기부 화면 데이터 기준: `data/사나리오 정의/TalkFile_종기부_컬럼정의서(컬럼기준)_v2.xlsx`. 새 정의서 2종(사업부서 · 영업점 v1)은 시드 JSON 으로 변환되어 저장소에 들어가 있다(컬럼 정의만, 실데이터 없음).
- 사용자 응답 · 문서는 한국어, 간결하게.

### 2.4 푸시 도우미 스크립트 (예전에 쓰던 것 — 키는 환경변수로)

```bash
#!/usr/bin/env bash
# usage: SRC=<작업 폴더> EXTRA_SECRETS="<LiteLLM 키>" push.sh <dest-dir> <dir>...
set -euo pipefail
SRC=${SRC:?작업 폴더}
DEST="$1"; shift
EXC=(--exclude node_modules --exclude .next --exclude __pycache__ --exclude '*.pyc' --exclude .pytest_cache --exclude .env --exclude '.env.local' --exclude backups --exclude '*.tsbuildinfo' --exclude .DS_Store --exclude '*.log' --exclude upload-fixtures --exclude .coverage)
for d in "$@"; do mkdir -p "$DEST/$d"; rsync -a --delete "${EXC[@]}" "$SRC/$d/" "$DEST/$d/"; done
for f in docker-compose.yml Makefile .env.example README.md; do cp "$SRC/$f" "$DEST/$f"; done
cd "$(git -C "$DEST" rev-parse --show-toplevel)"
git add -A
BAD=$(git diff --cached --name-only | grep -E '(^|nh-decision-platform/)data/|\.xlsx$|(^|/)\.env$|(^|/)backups/' || true)
[ -n "$BAD" ] && { echo "BLOCKED:"; echo "$BAD"; exit 3; }
for v in $(grep -E '^[A-Z_]+=' "$SRC/.env" | cut -d= -f2- | awk 'length($0)>=8') ${EXTRA_SECRETS:-}; do
  git diff --cached -U0 | grep -F -q -- "$v" && { echo "SECRET FOUND — abort"; exit 4; }
done
git diff --cached --stat | tail -3
```

- janlight: `push.sh <janlight 클론> apps/web apps/api apps/e2e .kiro/specs .kiro/steering infra .github docs`
- gogomovy: `push.sh <gogomovy 클론>/nh-decision-platform apps .kiro infra .github docs designsys` (루트 README 는 따로 수정 후 `git add README.md`)
- 주의: 금지 경로 정규식에 `(^|/)data/` 를 쓰면 `apps/web/src/components/data/` 가 걸린다 → 위처럼 루트 `data/` 만 막는다.

## 4. 아키텍처 요약 (어디를 고치면 되는가)

### 4.1 흐름
```
업로드(데이터셋 · 문서 · 정의서) / 규칙 · 설정 변경 / 정기 실행
  → ops.outbox_event (같은 트랜잭션)
  → dispatcher.match_event : 트리거(cfg.workflow_trigger) ∪ 계보(지표 · 바인딩이 읽는 데이터셋 · 정의서 적재 노드 표)
     + 오케스트레이터(LLM) 추가 경로(change.detected · document.ingested)
  → ops.job(디바운스 병합) → worker → workflow/engine 노드 순서 실행
     load_inputs → compute_metrics(커널) → judge → detect_changes(LLM) → build_views → (recommend · rank · tabs · guides)
     → plan_run(LLM 플래너) → retrieve_evidence(그래프 → 하이브리드) → narrate(LLM) → critic(규칙) → materialize_contracts → publish
  → view_artifact(화면 산출물 세대) · mart.<부서>_<표> · change_feed · agent_decision · llm_call · calc_run
  → 화면(/screens/*, 권한 = setting screen.resources)
```

## 10. 알려진 함정 · 트러블슈팅

- **Docker Desktop 이 멈춤** → `open -a Docker` 후 `docker info` 가 될 때까지 대기.
- **`/tmp` 가 재부팅 때 지워짐**(맥) → 스테이징 클론 · 도우미 스크립트를 다시 만든다.
- **맥 python3.9** 로 긴 한글 스크립트 실행 시 `python3 -c "exec(open(p,encoding='utf-8').read())"`. 엑셀은 컨테이너에서: `docker compose run --rm -T --no-deps -v "<데이터 폴더>:/defs:ro" api python /path/script.py`.

- **`timeout` 명령 없음**(맥) → 쓰지 않는다.
- **compose 명령은 compose 파일이 있는 폴더에서**(서버는 `nh-decision-platform` 안).
- **별도 스택 시험**: `docker compose -p nhdipe2e …` 는 기본 스택과 같은 이미지를 쓰므로 먼저 기본 스택 이미지를 최신으로 빌드. 포트 3100 · 8100 · 7574 · 7787. 끝나면 `docker compose -p nhdipe2e down -v`(그 스택 볼륨만 삭제).
- **정의서 목업값 불일치**: 2026.08 이 아닌 자료를 올리면 정상적으로 불일치가 나고 워크플로가 `degraded` 로 기록된다.
- **업로드 시험 후 기본 스택 데이터**: 업로드 시험은 기본 스택을 바꾸지 않는다. 기본 스택에서 직접 2026.09 자료를 올리면 골든셋(2026.08 기준)이 깨지고, 새 기준월 구획은 되돌리기(rollback)로 지울 수 없다 — 기본 스택에 올리지 말 것.
- **LLM 판단 쉬는 시간**: 판단 호출이 연속 오류면 300초 동안 규칙 판단(`agents.llm_judge.cooldown_sec`). 연결을 바꾸면 간단 설정 저장이 쉬는 시간을 풀어 준다.
- **Windows(Docker 없음)에서 DB 없는 시험만 돌릴 때**(2026-10-12 경험): `cd apps/api; python -m venv .venv; .venv\Scripts\pip install -r requirements.txt` 후 `$env:PYTHONPATH="src"; $env:DATABASE_URL="postgresql+psycopg://nhdip:nhdip@0.0.0.0:5432/nhdip"; .venv\Scripts\python -m pytest -q tests`. `localhost` 로 두면 시험마다 속도 제한 초기화가 DB 연결을 기다려(Windows 는 연결 거부에 약 2초 × 2) 매우 느리다 — `0.0.0.0` 은 즉시 실패. `lint-imports` 는 `$env:PYTHONUTF8="1"`(설정 파일의 한글 주석). `test_antivirus_hook` 은 `sh` 가 없어 실패하는 것이 정상.
- **Docker 없이 전체 검증(2026-10-12 방식)**: WSL 에 `apt install postgresql-18 postgresql-18-pgvector` → `pg_ctlcluster 18 main start` → 역할 `nhdip`(SUPERUSER) · DB 생성(WSL1 은 Windows 와 포트를 공유해 `127.0.0.1:5432` 로 접속). api 는 `alembic upgrade head` → `python -m nhdip.cli seed --with-precompute` → `uvicorn nhdip.main:app --port 8000`, worker 는 `python -m nhdip.worker`(환경변수는 compose 의 `x-api-env` 와 같게, `NEO4J_URI=bolt://127.0.0.1:1` 이면 그래프 축소 동작). 웹은 `NEXT_PUBLIC_DATA_SOURCE=api API_INTERNAL_URL=http://127.0.0.1:8000 npx next build` 후 standalone 폴더에 `.next/static` · `public` · `server-entry.cjs` 를 복사해 `node server-entry.cjs`(저장소 루트에 `package-lock.json` 이 있어 `server.js` 가 `standalone/nh-decision-platform/apps/web/` 아래에 생긴다). 그다음 `apps/e2e` 의 `e2e.mjs` · `a11y.mjs` · `upload-agents.mjs` 를 `E2E_BASE=http://127.0.0.1:3000` 으로. 시험 PDF 글꼴은 Windows 면 `C:/Windows/Fonts/malgun.ttf` 로 바꿔 생성. PowerShell 5.1 스크립트(.ps1)는 BOM 없는 UTF-8 한글 주석이 다음 줄을 먹을 수 있어 영어 주석으로.
- **Intl 날짜 · 시각 서식 금지(서버 렌더 화면)**: Node 와 브라우저의 ICU · hourCycle 이 달라 글자가 어긋난다(#418, Q90). 시각은 `lib/format` 의 문자열 함수(`formatDate` · `formatDateTime` · `formatKstDateTime`)로.
